# ADR 0005：CI 分层、统一门禁与初始化快照校验

- 状态：已接受
- 日期：2026-10-22

## 背景

历史重建后，整棵树成为根提交新增内容，旧尾随空格导致首次 Lint 失败；修复后的旧 HEAD 已通过完整 CI。每次仅改文档也重建两套 QEMU 镜像成本较高，而仅靠子任务绿色或跳过又可能漏掉失败。无 Docker Hub 发布目标时保留描述同步无意义，自动依赖 PR 也会与“仅留 master”的初始化策略冲突。

## 决策

- 保留常规静态、双架构合成、补丁和 smoke 检查；只有明确 docs-only 差异可跳过原生镜像。
- 根提交、未知基线、源码/配置/测试/CI 变更走完整原生 amd64/arm64 检查；发布强制 full=true。
- CI result 使用 always() 汇总必需结果，拒绝失败、取消、缺失输出与非预期 skipped；路由与门禁纳入回归测试。
- 全树 UTF-8/LF/尾随空格检查独立于历史，保留 commit whitespace 和补丁 apply 验证。
- 删除未使用 Docker Hub 描述同步；仅人工 GHCR 发布拥有 packages 写权限。
- 暂停 Dependabot 版本更新 PR，保留配置与人工依赖评审；不在本次更新基础镜像、QEMU 或依赖版本。
- 本轮依据维护者授权更新唯一初始化提交，备份原根；不删除历史失败 Actions 来伪装成功。

## 后果

文档路径拥有明确且可测试的轻量策略，运行时和发布不降低门禁。GitHub 所有旧 run 仍可能显示历史失败；当前结果按 SHA 查询。CI 仍不证明真实 DSM、ARC、KVM、摄像头或授权能力。

## 替代方案

- 关闭 whitespace 或忽略子任务失败：会掩盖错误，拒绝。
- paths-ignore 直接跳过整个 CI：没有稳定的完成门禁，拒绝。
- 所有提交无条件重建镜像：可靠但文档反馈慢；保留手动 full 与保守兜底。
